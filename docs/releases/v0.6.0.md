# v0.6.0

Covering v0.5.0 to v0.6.0. The release date is the tag's.

This release is mostly about the factory running without a person keeping it going. Runs that stop, whatever stopped them, are now found, recorded with a cause, and continued by the harness in their own session and worktree; decisions the development manager records on them are carried out ahead of fresh work; approved changes that lose the race to a moving main land instead of stranding; check stages no longer take hours under load; and the work tracker, whose store had grown to 930 MB, is cleaned up and measured by the harness itself. Beside those fixes come the machine home and `yoyo home migrate`, a supervisor that keeps every part of the product on the current build, the first part of integration through a merge queue, provider handling that keeps a run on the provider it started with, the release automation that cuts this tag, a new program manager role, memory for the roles, decisions taken from the dashboard, and support for working beside other contributors.

632 work items closed between v0.5.0 and this release with a change on `main`. They are grouped here by what they changed rather than listed one by one, so these notes stay readable and within what a release page can carry; every one of them is named by its identifier under the entry it belongs to, and the tracker holds each item's full description.

Each entry below names the goals its work served, by the identifier the goals documents give them:

- `[nearly-autonomous]` Run development nearly autonomously.
- `[plain-language]` The harness's surfaces read clearly: boundaries between topics and speakers are visible, important findings stand out, every distinction survives a terminal that cannot render emphasis, and user-facing language chooses the ordinary, literal word over metaphor, coinage, or term of art.
- `[traceable-chain]` Maintain a traceable chain from the product brief through goals, designs, work, code changes, and verification.
- `[no-silent-redefinition]` Let configurable agent roles collaborate without allowing downstream agents to silently redefine upstream intent.
- `[configurable-safely]` Keep roles, policies, and provider selection configurable without making safety invariants optional, and support multiple providers behind one adapter contract.
- `[isolated-worktrees]` Isolate implementation tasks in harness-managed Git worktrees and integrate successful work automatically.
- `[readme-first-run]` A newcomer can go from the documented install to a working first run on their own repository using the readme alone.
- `[independent-review]` Every change is reviewed against the intent it claims to serve, by a role that did not write it, before it is integrated.
- `[spend-follows-the-work]` Spend follows the work: the model, the context, and the number of provider calls a task costs are chosen for that task rather than for the role that does it, and running cost is visible and classified so the operator can see what each kind of work costs and decide what it should.
- `[shared-repository]` A team can run Yoyodyne against one shared repository: collaborators each run their own harness without losing work, splitting the tracker, or weakening any safety invariant.
- `[visible-spend]` The operator can see what the harness spends on their behalf: provider-reported cost, per work item, per run, and in total.
- `[harness-publishes]` Publish that work as pull requests the harness opens, and has the forge merge, on the roles' behalf, for projects that enable it, without letting any agent push or merge.
- `[any-language]` Support development in any language.
- `[internal-week-bar]` Before any outside trial, Yoyodyne runs one week on its own repository in which no hour passes with ready work waiting and a developer slot idle, nothing is asked of the owner that the harness or a role could have done, and the management roles' spend is at most 40% of all known spend for the week.
